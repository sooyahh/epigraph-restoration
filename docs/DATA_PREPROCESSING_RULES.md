# DATA_PREPROCESSING_RULES.md — 데이터 전처리 및 분할 규칙

금석문 판독문을 학습·평가 데이터로 만들 때 지키는 현재 규칙이다. 마지막 상태 정합화 날짜는 **2026-07-11**이다.

> **원본은 절대 수정·이동·삭제하지 않는다.** 가공 결과는 새 파일로 만들고, 생성 코드·규칙 버전·입력 버전을 함께 기록한다.

## 1. 데이터 상태와 용어

- 현재 전처리 규칙 버전은 `gsm_preprocess_v4`다.
- `readings.csv`는 1차 가공본이며 전수 수동 검수를 마친 공식 corpus가 아니다.
- 행 수, 비문 수, split 단위 수, 마스크 샘플 수는 서로 다른 단위다. 모든 수치에는 단위를 붙인다.
- 현재 기록된 주요 수치는 `readings.csv` 14,702행, 학습 대상 7,158행, 인공 마스크 샘플 66,537개다.

## 2. 원본과 가공 레이어

1. **raw:** XLS/XML/PDF 등 출처 원본과 원래 결손 표기를 보존한다.
2. **processed:** 정규화한 판독문, 품질 플래그, 결손 여부, 규칙 버전을 보관한다.
3. **model inputs:** split과 인공 마스킹을 적용한 학습·평가 입력을 보관한다.
4. **outputs:** 예측, 지표, 체크포인트를 보관한다. 대용량 파일이 Git 밖에 있으면 외부 백업 위치와 SHA-256을 기록한다.

각 파생 파일은 어느 입력과 코드로 생성됐는지 역추적할 수 있어야 한다.

## 3. 문자 정규화 규칙

- 처리 기본 단위는 한 글자(character)이며 단어 분절을 하지 않는다.
- 코드가 원문에 없는 한자를 추정해 삽입·치환하지 않는다.
- 판독문이 아닌 제목, 해설, 소재지, 구조 표기와 주석은 학습 본문과 분리한다.
- 공백·줄바꿈 제거 여부는 위치 인덱스와 문맥에 영향을 주므로 코드의 현재 동작과 변경량을 확인한 뒤 결정한다.
- NFC/NFKC는 한자 호환문자를 합칠 수 있으므로, 변환되는 문자 목록과 빈도를 감사하기 전에는 임의로 변경하지 않는다.
- 이체자는 원문을 보존한다. 평가상 동치 처리는 검증된 매핑 출처가 정해진 후 별도 레이어에서 수행한다.

## 4. 결손과 한글 혼입

`gsm_preprocess_v4`의 확정 규칙은 다음과 같다.

| 기호 | 의미 | 사용 위치 |
|---|---|---|
| `□` | 원문 결손·판독 불가 표기에서 온 실제 결손 | processed 및 실제 결손 추론 |
| `◇` | 잔존 한글 또는 한글 혼입을 위치 보존 목적으로 치환 | processed의 review 대상 |
| 모델 mask token | 정답을 아는 한자를 인공적으로 가린 위치 | 학습·validation·test |

- `has_real_defect`와 `defect_count`는 실제 결손에서 온 `□`만 집계한다.
- `◇`를 실제 결손으로 집계하거나 실제 결손 데모에 넣지 않는다.
- 실제 결손이 포함된 판독문은 현재 baseline의 인공 마스크 학습 원천에서 제외한다.
- 결손, 한글 혼입, 부분 판독, 추정 복원이 원천에서 구분된다면 별도 메타데이터로 보존한다.
- 결손률에 따른 제외 임계값은 아직 확정하지 않았으므로, 실험 전에 분포와 표본을 먼저 검토한다.

## 5. 학습 샘플 구성

인공 마스크 샘플에는 최소한 다음 정보가 있어야 한다.

- 원천 판독문 또는 이를 추적할 수 있는 식별자
- 마스크가 적용된 입력
- 정답 글자
- 마스크 위치
- inscription 또는 split 단위 식별자
- train/valid/test 구분
- 전처리 규칙 버전

정답 글자는 모델 입력에 노출되면 안 된다. 한 판독문에서 여러 샘플을 만들 경우 특정 장문·비문이 과대표집되는지 점검한다.

## 6. train / validation / test split

- 같은 비문은 하나의 split에만 속하게 한다.
- 현재 split은 inscription 단위, `seed=42`로 생성됐고 동일 비문의 split 간 교집합은 0건으로 재검증됐다.
- 현재 인공 마스크 샘플 수는 train 46,139 / valid 10,679 / test 9,719다.
- `6,084 split 단위`, `3,395 마스크 데이터 포함 비문`처럼 서로 다른 집계값은 정의를 함께 기록한다.
- 문자 단위 랜덤 split은 기본 평가로 사용하지 않는다.
- inscription split이 있어도 다른 비문 사이의 동일 정형구가 남을 수 있으므로 n-gram 중복을 별도로 측정한다.
- 모델·epoch·하이퍼파라미터 선택은 validation으로만 수행한다.
- test는 최종 모델 비교에 제한적으로 사용하고, 열람·평가 목적과 횟수를 실험 로그에 기록한다.

## 7. tokenizer와 문맥 길이

- 정답이 tokenizer의 UNK이면 해당 고정 vocabulary 모델이 그 글자를 직접 출력할 수 없음을 별도 집계한다.
- 원문 글자 수와 subword token 수를 혼동하지 않는다.
- 장문 truncation 시 마스크 위치가 보존되고 좌우 문맥 창이 의도대로 잘리는지 경계 사례를 테스트한다.
- 모델별 mask token, special token, top-k 중복 제거 규칙을 명시한다.

## 8. 데이터 버전과 재현성

각 데이터 버전에는 다음을 기록한다.

- 입력 파일명과 가능하면 SHA-256
- 전처리 규칙 버전
- 생성 코드와 Git 커밋
- 실행 명령
- 생성 날짜
- 행·비문·샘플 수
- 품질 플래그와 제외 통계
- split 기준과 seed

자동 추출·미검수 결과에는 `candidate` 또는 `unverified`를 표시한다. 기존 산출물은 재현성 근거이므로 임의로 덮어쓰지 않는다.

## 9. 실행 전 체크리스트

- [ ] 원본을 수정하지 않았다.
- [ ] 실제 결손 `□`와 한글 치환 `◇`가 분리됐다.
- [ ] 학습 입력에 정답이 노출되지 않는다.
- [ ] 같은 비문이 여러 split에 걸치지 않는다.
- [ ] validation으로 모델을 선택하고 test 사용을 제한했다.
- [ ] 장문 truncation과 마스크 위치를 확인했다.
- [ ] UNK 정답 비율을 기록했다.
- [ ] 비문별 샘플 수 쏠림을 확인했다.
- [ ] 데이터 버전, 코드, seed, 생성 명령을 기록했다.
- [ ] 대용량 산출물의 외부 백업과 체크섬을 확인했다.
