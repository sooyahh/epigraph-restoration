# PROMPTS.md — 반복 사용 프롬프트 모음

GPT/Claude/Gemini/Codex에게 반복해서 시키는 작업의 프롬프트 템플릿이다.
매번 새로 쓰지 말고 여기서 복사해 `[ ]` 부분만 채워 쓴다.
모든 프롬프트는 공통적으로 **목표 / 입력(파일 경로) / 제약 / 원하는 출력 형태**를 포함한다.

> 공통 제약(항상 붙이기): "원본 데이터는 수정·이동·삭제하지 마라. 결과는 새 파일로 제안하라. 데이터 누수(같은 유물이 train/test에 섞이는 것)를 피하라. 확신 없는 부분은 단정하지 말고 TODO로 표시하라."

---

## 1. 데이터 분석 검토 프롬프트 (주로 GPT/Claude)

```
역할: 너는 금석문 한자 결손복원 프로젝트의 데이터 분석 검토자다.
목표: 아래 데이터/분석 결과에 통계적·논리적 문제가 있는지 점검하라.
입력: [파일 경로 또는 분석 요약 붙여넣기]
점검 항목:
1. 데이터 누수 위험(특히 train/valid/test split 기준이 inscription 단위인지)
2. 결손(□) 표기와 라벨 분리가 제대로 되어 있는지
3. 분포 편향(시대/길이/결손비율 쏠림)
4. 결론이 데이터로 뒷받침되는지, 과장은 없는지
출력 형태:
- 발견한 문제 목록(심각도 표시)
- 각 문제의 근거
- 권장 수정안
- 확신 없는 부분은 TODO로 표시
```

## 2. 논문/자료 조사 프롬프트 (주로 Gemini/GPT)

```
역할: 너는 고문헌/비문 복원 분야의 리서치 보조다.
목표: [주제, 예: 한자 결손문자 복원 / 이체자 기반 평가]에 대한 핵심 방법과 사례를 정리하라.
요구:
1. 대표 논문/시스템 3~5개의 핵심 아이디어
2. 공개 코드·데이터 유무와 재현 가능성(상/중/하)
3. 우리 과제(한국 금석문, character-level, top-k 후보)에 적용 가능성
4. 한 달 반 캡스톤에서 실현 가능한지 여부
출력 형태:
- 표(논문명 | 핵심 아이디어 | 코드유무 | 재현성 | 우리 적용성)
- 추천/비추천과 이유
- 모든 사실에 출처(링크) 표기. 출처 없으면 "미확인"으로 표시
```

## 3. 전처리 코드 구현 프롬프트 (주로 Codex/Claude)

```
역할: 너는 데이터 전처리 코드를 작성하는 엔지니어다.
목표: [예: 원문에서 original_text / masked_input / label 3개 컬럼을 생성하는 스크립트]를 작성하라.
입력: [입력 파일 경로와 컬럼 구조]
제약:
- 원본 파일은 읽기만 하고, 결과는 새 파일(예: outputs/)로 저장
- 결손은 □로 통일하되 raw 표기는 별도 컬럼에 보존
- split은 inscription_id 단위(누수 방지). split 기준/시드를 인자로 받게
- 함수 단위로 작성하고, 작은 예시로 동작 확인 코드 포함
출력 형태:
- 실행 가능한 파이썬 코드
- 사용법(명령어 예시)
- 생성되는 출력 파일 설명
```

## 4. 코드 리뷰 프롬프트 (주로 Claude/GPT)

```
역할: 너는 코드 리뷰어다.
목표: 아래 코드를 정확성·데이터 누수·재현성·단순성 관점에서 검토하라.
입력: [코드 또는 파일 경로]
점검 항목:
1. 정답 라벨이 입력으로 새어 들어가지 않는가(누수)
2. split 기준이 의도대로(inscription 단위) 동작하는가
3. 랜덤 시드 고정 등 재현성이 보장되는가
4. 평가 지표(Exact@k, Group@k) 계산이 올바른가
5. 한 달 반 일정에 비해 불필요하게 복잡하지 않은가
출력 형태:
- 문제별 (위치 / 심각도 / 설명 / 수정 제안)
- 꼭 고쳐야 할 것 vs 나중에 봐도 될 것 구분
```

## 5. 발표자료 작성 프롬프트 (주로 GPT/Claude)

```
역할: 너는 캡스톤 발표를 돕는 발표 코치다.
목표: 아래 내용으로 발표 슬라이드 구성안을 만들라.
입력: [프로젝트 개요 + 최신 실험 결과 + 핵심 예시]
요구:
1. 슬라이드 흐름: 문제 → 데이터 → 방법 → 결과(지표/예시) → 차별성 → 한계/향후
2. 각 슬라이드의 제목과 핵심 한 줄, 들어갈 시각자료 제안
3. 심사위원이 할 만한 예상 질문 5개와 모범 답변
제약:
- 우리가 직접 설명할 수 있는 수준으로(과장·미검증 수치 금지)
- 수치는 EXPERIMENT_LOG의 실제 결과만 사용
출력 형태:
- 슬라이드별 개요(번호 | 제목 | 핵심 메시지 | 시각자료)
- 예상 Q&A
```

## 6. GrokBot 자율 실행 프롬프트 (2026-09-17 추가, DECISIONS [016])

GrokBot은 사람의 매 턴 확인 없이 여러 앱에 로그인해 장시간 자율로 작업을 이어가는 에이전트다.
그래서 아래 세 템플릿에는 공통 제약 위에 **승인 지점**과 **완료 증명 방식**을 반드시 명시한다.

> GrokBot 공통 제약(항상 붙이기, 위의 공통 제약에 추가): "작업 완료를 스스로 선언하지 말고, 실제 생성된 파일 경로·로그·수치로 증명하라. git add/commit/push는 절대 하지 마라. `data/raw_layer/` 등 원본 데이터를 수정·이동·삭제하지 마라. 지정된 승인 지점에 도달하면 실행을 멈추고 사람의 확인을 기다려라."

### 6-A. EXP-018 GPU 학습 모니터링·백업

```
역할: 너는 GPU 학습 작업을 모니터링하고 산출물을 백업하는 보조 작업자다.
목표: [Colab/GPU 환경]에서 [018C(lr=2e-5) 등] 학습 설정으로 finetune_sillokbert.py를 실행하고,
      완료 후 체크포인트를 외부 저장소(Drive 등)에 백업한다.
입력: 실행 명령 및 설정값 [붙여넣기], 기존 체크포인트 경로(덮어쓰기 금지 확인용) [경로].
제약: notebooks/best/, outputs/finetune/exp018/ 등 기존 산출물 경로를 덮어쓰지 마라.
      스크립트 자체를 수정하지 말고 주어진 명령으로만 실행하라.
승인 지점: 예상 컴퓨트 시간/비용을 초과할 것 같으면 실행 전 반드시 승인을 요청하라.
완료 조건(반드시 아래를 제시):
- 생성된 체크포인트 파일 경로 전부와 각 파일의 SHA-256
- 외부 백업(Drive 등) 링크
- epoch별 train/valid loss 로그(표 형태)
보고 형식: 실행 명령, 소요 시간, 위 완료 조건 항목, 발생한 오류/경고.
```

### 6-B. 논문·2차 원천 조사 자동화

```
역할: 너는 고문헌/비문 복원 분야 및 관련 데이터 원천을 조사하는 리서치 보조다.
목표: [조사 주제, 예: 국사편찬위 XML 2차 원천의 통합 가능성 / 특정 논문의 재현성]을 조사하라.
제약: 조사와 후보 제시까지만 하고, 실제 데이터 통합·다운로드 실행이나 원본 데이터 수정은 하지 마라.
      통합 여부는 팀이 DECISIONS.md에서 별도로 결정한다.
완료 조건(출처 링크·수집일자 없는 항목은 결과에 포함하지 마라):
- 표(출처 | 핵심 내용 | 재현성(상/중/하) | 우리 프로젝트 적용 가능성 | 수집일자 | 출처 링크)
- 확신 없는 부분은 "미확인"으로 표시
보고 형식: 위 표 + 요약 3~5줄 + 다음에 사람이 확인해야 할 질문 목록.
```

### 6-C. EXP-019 ARI-8B 하이퍼파라미터 반복 실행

```
역할: 너는 ARI-8B Top-K 후보 생성 하이퍼파라미터 sensitivity 실험을 반복 실행하는 보조 작업자다.
목표: docs/ARI_TOPK_DESIGN.md에 정의된 [B1/B2/Lmax 후보 조합 목록]에 대해
      순서대로 실행하고 각 조합의 valid subsample Exact@5와 실행 로그를 기록한다.
제약: Top-K 후보 생성 규칙(constrained decoding 알고리즘) 자체를 임의로 바꾸지 마라 — 이미 설계·고정된 규칙만 사용하라.
      정해진 조합 목록 밖의 값을 임의로 추가하지 마라.
승인 지점: 사람이 최초 1개 조합의 성공 실행(정상 종료, 로그·결과 파일 생성)을 직접 확인하기 전까지는
      나머지 조합을 반복 실행하지 말고 대기하라. OOM/에러 발생 시 즉시 실행을 멈추고 보고하라.
완료 조건:
- 조합별 결과 CSV(설정값 | Exact@5 | 실행 시간 | 오류 여부) 경로
- 각 실행의 원본 로그 파일 경로
보고 형식: 위 CSV/로그 경로, 실패한 조합과 원인, 재실행 필요 여부.
```
