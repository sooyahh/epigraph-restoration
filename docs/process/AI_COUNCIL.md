# AI_COUNCIL.md — AI 협업 운영 규칙

여러 AI 도구를 사용할 때 진행 상황과 책임이 흩어지지 않도록 하는 운영 규칙이다. 특정 제품의 능력을 고정해서 구분하지 않고, **작업 유형·권한·검증 절차**로 역할을 나눈다. 마지막 갱신일은 **2026-07-11, 2026-09-17(자율 에이전트/GrokBot 가드레일 추가)**이다.

## 1. 기본 원칙

1. AI는 제안·조사·구현·검증을 도울 수 있지만 프로젝트 결정과 외부 제출 책임은 사람에게 있다.
2. AI의 설명이 아니라 실제 파일, 명령 출력, 실험 산출물을 근거로 완료 여부를 판단한다.
3. 한 작업에는 하나의 명확한 목표와 제한된 수정 범위를 둔다.
4. 중요한 변경은 다른 도구 또는 사람이 독립적으로 검토한다.
5. 실행하지 않은 작업, 존재하지 않는 파일, 확인하지 않은 수치를 만들어내지 않는다.

## 2. 작업 유형별 도구 선택

| 작업 유형 | 적합한 작업 환경 | 필수 검증 |
|---|---|---|
| 방향·우선순위·대안 비교 | 대화형 AI 또는 저장소를 읽을 수 있는 작업 환경 | 실제 프로젝트 상태와 대조, 사람 승인 |
| 저장소 전체 감사 | Git·파일·명령 실행이 가능한 환경 | `git status`, 경로 존재, 코드·산출물 대조 |
| 코드 구현·리팩터링 | Codex, Claude Code, Cursor 등 저장소 작업 도구 | 테스트, diff, 변경 파일 보고 |
| 작은 인라인 수정 | 편집기 내 AI | 수정 범위 확인, 관련 테스트 |
| 외부 논문·모델·라이선스 조사 | 웹 검색 가능한 AI | 공식 문서·원논문 링크와 날짜 |
| 문서·발표 구성 | 대화형 또는 문서 작업 AI | 모든 주장과 수치를 실험 로그에 연결 |
| 장시간 학습 | 로컬 GPU·Colab 등 실행 환경 | 로그·설정·체크포인트·중단 복구 |
| 장시간 자율 실행·다중 앱 로그인이 필요한 반복 작업 (예: GPU 학습 모니터링·백업, 반복 하이퍼파라미터 실행, 다건 자료 조사) | GrokBot 등 자율 에이전트 환경 (§7 범위 내) | 실행 완료 후 실제 산출물(체크포인트/로그/CSV/출처 링크)이 존재하는지 사람이 직접 확인 — 자기 완료 보고를 근거로 삼지 않음 |

도구 이름만으로 신뢰 수준을 정하지 않는다. 같은 도구라도 현재 세션의 파일·웹·실행 권한에 따라 할 수 있는 일이 달라진다.

## 3. 표준 작업 요청 형식

AI에게 다음 항목을 한 번에 제공한다.

1. **목표:** 무엇을 완료해야 하는가
2. **현재 상태:** 브랜치, 관련 실험·결정, 알려진 문제
3. **입력:** 읽을 파일과 데이터 경로
4. **수정 허용 범위:** 변경 가능한 파일
5. **금지 작업:** 삭제, commit, push, 데이터 재생성 등
6. **완료 조건:** 테스트, 수치, 산출물
7. **보고 형식:** 변경 파일, 명령, 결과, 남은 위험

작업 예:

```text
목표: EXP-012 완료 상태를 문서에 반영한다.
근거: EXPERIMENT_LOG EXP-012, DECISIONS [010], notebooks/best/.
수정 허용: 지정한 docs만.
금지: 코드·데이터 수정, 실험 실행, commit, push, 모델 Git 추가.
완료 조건: EXP-012 full-test 완료와 EXP-011 subsample 구분이 함께 적혀 있다.
보고: 변경 파일과 문장별 근거.
```

## 4. 작업 전·후 절차

### 작업 전

- 현재 브랜치와 `git status`를 확인한다.
- 사용자 미커밋 변경과 AI가 만들 변경을 구분한다.
- 관련 `PROJECT_OVERVIEW.md`, `EXPERIMENT_LOG.md`, `DECISIONS.md`를 읽는다.
- 수정 파일과 금지 작업을 명시한다.

### 작업 후

- 변경 파일 목록과 핵심 diff를 보고한다.
- 실행한 명령과 테스트 결과를 그대로 보고한다.
- 실행하지 못한 검증과 남은 위험을 구분한다.
- `git add`, commit, push는 요청된 범위에서만 수행한다.
- 중요한 실험과 결정은 해당 로그에 연결한다.

## 5. 완료 판정

다음 중 하나라도 충족하지 않으면 `완료`가 아니라 `부분 완료` 또는 `미검증`이다.

- 요청한 산출물이 실제 경로에 존재한다.
- 코드 변경은 관련 테스트를 통과했다.
- 성능 수치는 예측 파일 또는 로그에서 재집계할 수 있다.
- 데이터 수치는 CSV 파서 등 올바른 방식으로 확인됐다.
- 문서의 완료 상태가 실제 실험 범위와 일치한다.
- Git 밖의 중요 산출물에는 백업 위치와 체크섬이 있다.

## 6. AI 간 의견 충돌

1. 충돌하는 주장과 근거를 표로 정리한다.
2. 저장소·원본 데이터·공식 문서로 확인 가능한 것은 직접 확인한다.
3. 확인이 어려우면 가장 작은 비교 실험을 설계한다.
4. 사람이 대안·이유·리스크를 검토해 결정한다.
5. 결정과 검증 계획을 `DECISIONS.md`에 기록한다.

AI 수를 늘리는 것 자체는 교차검증이 아니다. 서로 같은 문서나 이전 AI의 결론만 재진술했는지 확인한다.

## 7. 현재 프로젝트의 특별 규칙

- EXP-011은 CPU 1 epoch subsample baseline이며 최종 성능이 아니다.
- test 기반 결과를 더 이상 하이퍼파라미터 선택에 사용하지 않는다.
- EXP-011의 legacy `EXP-006` 파일은 원본을 보존하되 공식 표기는 `EXP-011`로 통일한다.
- `backup/cursor-local-ahead`와 stash는 자동 병합·삭제하지 않고 파일별로 검토한다.
- 체크포인트와 대용량 예측은 일반 Git에 무조건 추가하지 않는다. 외부 백업 또는 합의된 LFS 정책을 사용한다.
- 존재하지 않는 `CLAUDE.md`나 스크립트를 전제로 작업하지 않는다. 실제 저장소에서 경로를 먼저 확인한다.
- **(2026-09-17 추가) 자율 에이전트(GrokBot 등)에게 위임 가능한 작업은 현재 3가지로 한정한다: EXP-018 GPU 학습 모니터링·체크포인트 백업, 논문·2차 원천 조사 자동화, EXP-019 하이퍼파라미터 반복 실행(DECISIONS [016]).**
- **(2026-09-17 추가) 자율 에이전트에게는 사람이 명시적으로 요청해도 git add/commit/push, `data/raw_layer/` 등 원본 데이터 쓰기, ARI Top-K 설계 규칙(`docs/ARI_TOPK_DESIGN.md`) 자체의 변경을 위임하지 않는다.**
- **(2026-09-17 추가) 자율 에이전트의 "완료했다"는 보고는 그대로 신뢰하지 않는다. 실제 체크포인트 경로·SHA-256·로그·출처 링크+수집일자로 재확인한 뒤에만 `EXPERIMENT_LOG.md`/`DECISIONS.md`에 반영한다.**
